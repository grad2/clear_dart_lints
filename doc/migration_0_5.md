# Migrate to 0.5.0

Version 0.5.0 intentionally breaks schema 1 configuration and the old architecture diagnostic names. There is no compatibility mode. Keep the existing optional style rules and quick fixes; replace the architecture policy before upgrading the plugin in CI.

1. Select a [complete schema 2 template](../templates/README.md) that fits the project's framework and folder layout. Copy and adapt it rather than changing only `schema_version` in the old file.
2. Add required `include` and disjoint `layers` coverage for every included physical source. Classify `main.dart`, bootstrap, shared core and parts. Put generated exclusions in `exclude` explicitly; filename suffixes and generated markers no longer automatically skip architecture.
3. Replace `layer_dependencies.source_layers` / `forbidden` with `layer_dependencies.allowed`. The new graph **denies by default**: explicitly permit same-layer edges, SDK libraries, external package URIs and local target layers. A local package URI permission cannot bypass local layer classification.
4. Replace `repositories_only_in_blocs` with general `role_dependencies.restrictions`. Define `dependency_roles` and `allowed_consumer_roles`; use resolved `Bloc` or `Cubit` `types` identities instead of relying on names ending in `Bloc`. Preserve any deliberate path/name selectors for other roles.
5. Separate `depend_on_contracts` (abstract dependency type) from `constructor_injection` (acquisition and field origin). Configure both where the previous policy expected both. Declare composition roots for each applicable rule and give the app layer its actual dependency edges.
6. Replace `no_transport_in_domain` with an explicit allowed layer/URI graph plus `forbidden_symbols` for particular declaration identities. Add a role restriction for transport roles if needed. A domain allowlist of basic SDK libraries prevents importing transport packages; symbol restrictions can be narrower than an entire library.
7. Remove old architecture diagnostic enable/disable entries. Architecture is automatically on as warnings. Keep desired optional style diagnostics under `plugins.clear_dart_lints.diagnostics`. Remove architecture ignore comments and severity reductions; use a reviewed narrow `exceptions` entry with a reason for a supported policy rule when necessary. Structural classification/configuration failures cannot be excepted.
8. Pin the plugin and verifier dev dependency to matching `0.5.0` installations, resolve dependencies, restart the Analysis Server, then run the [two-command verification gate](agent_integration.md#3-establish-a-visible-baseline).

The new architecture diagnostic codes are `invalid_configuration`, `unclassified_source`, `ambiguous_layer`, `layer_dependencies`, `role_dependencies`, `depend_on_contracts`, `constructor_injection`, `forbidden_symbols`, and `unverifiable_dependency`. They use the `clear_dart_lints/` prefix in analyzer configuration/comments. Optional Effective Dart and style diagnostic names remain unchanged.

Treat prior “all informational / all opt-in” documentation as applying only to optional styles in 0.5.0. Architecture is a default warning policy, and the read-only setup audit checks that it has not been hidden. The audit is not a second architecture analyzer. For the complete field reference and limitations, see [configuration semantics](configuration.md).
